# cc-244 postmortem

## What went right

The ticket identified the persistence mismatch precisely: the loader read Forecast state, but the YAML writer omitted it. Persisting forecast_active and forecast_cards fixed the request lifecycle without changing game rules. Existing loader defaults preserved compatibility with older saves.

The replacement regression test failed before the fix and passed afterward. It starts Forecast through HTTP, reloads production YAML, verifies card consumption and blocked movement without saved-state changes, submits a reordered deck through another request, reloads the completed state, and confirms actions resume. Separate coverage checks older saves without the fields. The full suite passed with 129 tests and 759 assertions. The fix was committed as 6d7d6bd and subsequently reported merged.

## What went wrong

The previous blocking test seeded a GameState object through Marshal, bypassing production YAML serialization. It verified an in-memory flag survived Marshal rather than checking that starting Forecast remained actionable on the next request. This allowed the event card to be consumed while its pending operation disappeared.

Inspection also found that Forecast order validation accepts duplicate card names when length and membership checks pass. This separate issue is already tracked in cc-251, which remains open; no duplicate bug ticket was created during wrap-up.

## Final thoughts

Multi-request game operations need regression coverage through the actual persistence format. The implemented lifecycle and compatibility tests cover the requested fix, so an additional test ticket would duplicate completed work. TechnicalDesign (cc-35) now documents the saved fields, compatibility defaults, and regression coverage in a description under 500 words. FunctionalDesign and ApiAuth were reviewed; this fix restores their existing behavior without changing the rules or API schema.

The remaining duplicate-order validation issue belongs in cc-251. This postmortem is intentionally uncommitted for dispatcher publication.
