# cc-239: Error messages

## What went right

Reading cc-118, cc-34, and cc-117 established the UI and API context. Inspection identified all three temporary notification implementations: player actions, Share Knowledge, and game restart. A shared reporting helper now preserves displayed errors in the console and sends them to Sentry when configured. Invalid-action warnings retain warning severity. Reporting failures are isolated so notifications still appear and dismiss normally.

The implementation was committed as 19b9bd6 and accepted. All 16 existing JavaScript tests and 128 Ruby tests passed. Ad hoc smoke checks covered console-only operation, Sentry capture severity, success filtering, and capture failures. No tests were added to the suite, as requested.

## What went wrong

There was no existing Sentry integration or project DSN in the repository, so implementation required conditional SDK loading and deployment configuration. Live delivery could not be verified; existing follow-up cc-242 tracks configuring the public SENTRY_DSN and checking receipt in Sentry.

The initial reporting module assumed the test DOM provided querySelector, breaking the independent-module import test. Guarding the optional DOM lookup fixed that failure without changing tests. The reporting behavior currently has only ad hoc verification beyond existing regression tests; cc-243 now specifies automated coverage for notification paths, configuration, SDK failures, and dismissal behavior.

## Final thoughts

Centralized reporting preserves transient failures for diagnosis while keeping notification behavior intact. FrontendUI (cc-118) now documents the reporting and configuration contract. FunctionalDesign (cc-34) and ApiAuth (cc-117) were reviewed and needed no changes because gameplay and API/authentication contracts did not change.

The existing deployment follow-up was retained rather than duplicated. No additional unresolved bug was identified during wrap-up. This postmortem is intentionally uncommitted for dispatcher publication; no application files were changed during wrap-up.
