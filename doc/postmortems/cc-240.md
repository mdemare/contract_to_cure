# cc-240: Player roster overlap

## What went right

The screenshot led to two concrete causes: selection styles enlarged roster pawns beyond their grid columns, and nonwrapping role names extended into turn badges. Scoping selection pawn rules to selection buttons restored the roster dimensions. Wrapping titles, locations, and card names retained complete information within the compact drawer. Removing card hover translation prevented previews from crossing neighboring rows.

The implementation was committed as 8b10dba and accepted. All 128 existing tests passed with 742 assertions. One existing CSS assertion was updated to expect wrapping; no tests were added. A temporary Chromium check using the production stylesheet order confirmed no measured collisions at 1280px, 375px, and 280px viewport widths. Four representative seven-card hands occupied about 480px at standard drawer width. A screenshot was also inspected.

## What went wrong

Shared pawn class names allowed styles from a different UI surface to override the roster. The title layout assumed short text, while card previews forced single-line names into narrow columns. Existing DOM and CSS-source tests could pass without detecting these rendered geometry problems. Their height estimate also does not account for font-dependent wrapping.

The temporary browser check did not load the remote production fonts, so its measurements establish fallback-font behavior rather than complete typography coverage. At the narrowest viewport the roster grew to about 502px, reinforcing the need to preserve outer scrolling rather than enforce a fixed total height.

## Final thoughts

Keep component-specific dimensions scoped to their owning surface and let text determine row height. The correction preserves turn order, full hands, and existing gameplay behavior.
