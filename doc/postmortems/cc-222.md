# Transparent canvas disease cubes

## What went right

Disease cubes moved from city DOM elements to a dedicated transparent canvas
inside the transformed map surface. Individual pieces orbit their authoritative
city positions, with evenly spaced angles and matching phases across the three
wrapped panels. The canvas inherits map transforms and leaves city interactions
to the existing buttons. Accessible city descriptions retain cube totals.

The renderer handles device pixel ratio scaling, reduced-motion preferences,
and cancellation of old animation frames and observers when the map rerenders.
Empty maps do not schedule continuous animation. The existing dense-map check
caught label collisions caused by the larger orbital footprint; increasing
infected-city label clearance fixed that failure.

Implementation verification passed with 128 tests and 742 assertions using
bundle exec rake test, plus JavaScript syntax and a recording-context smoke
check. Existing tests were adjusted without adding new tests, as requested.
The implementation was committed as 0e006f6 and subsequently accepted.

## What went wrong

The smoke check exercised drawing calls and sizing, but did not validate actual
browser pixels or interaction. A browser check was announced but no installed
browser was found and no browser validation was completed. The passing suite
therefore did not establish that the canvas remained visible during panning.

Wrap-up review found that canvas height follows the viewport rather than all
city orbit extents. With a 300px map height, Cape Town's city center is at map
Y=465 and its three cube centers are approximately Y=464, 481, and 450, outside
the bitmap. Panning upward by 300px brings the city into view at Y=165, but
cannot recover the clipped cube pixels. This was confirmed with a recording
context and filed as bug cc-228; no implementation files were changed during
wrap-up.

The existing tests check accessible counts and layer styles but do not cover
the new animation lifecycle. After checking existing cards, including the
closed general map visual-test ticket cc-206, a distinct test ticket cc-229
was filed for drawing, orbital timing, rerender cleanup, reduced motion,
resizing, and browser interaction. It calls for coordinating the clipping
regression with cc-228 to avoid duplicate work.

## Final thoughts

Separating decorative pieces from interactive city controls kept the change
focused, but sharing a CSS transform does not guarantee that a canvas covers
the same drawable area as overflowing DOM content. Future verification needs
to check both alignment and bitmap coverage at short viewport heights.

FrontendUI (cc-118), TechnicalDesign (cc-35), and FunctionalDesign (cc-34) now
describe the canvas presentation, orbital label clearance, and reduced-motion
behavior. Each description remains below 500 words. This postmortem is the
only repository file changed during wrap-up and is intentionally uncommitted
for dispatcher publication.
