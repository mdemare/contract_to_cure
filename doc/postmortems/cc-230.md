# cc-230: Expert used move blocks flights

## What went right

The defect was isolated to movement branch eligibility. Gating the Operations Expert branch on the unused ability allows ordinary direct and charter flight handling to run after the special move has been spent. Existing behavior while the ability is available remains intact.

The existing API integration test was extended without adding a new test method. It covers direct and charter flights, both matching cards with explicit selection, requests for card selection, and rejection of an unrelated card. Assertions verify card and action consumption, the preserved ability flag, and unchanged saved state for unsuccessful requests. The implementation run of `bundle exec rake test` passed with 129 tests and 800 assertions. GameRules documents the corrected behavior.

## What went wrong

The original branch rejected every qualifying station departure after the ability was used, before evaluating ordinary flights. The initial regression fixture also tried to use a nonexistent setter; changing it to the established instance-variable setup fixed the test error before the successful full-suite run.

The ticket referenced `route_context.js`, its tests, and cc-194, but the files were absent and cc-194 could not be retrieved. A bug follow-up, cc-253, was created for projection alignment and its test coverage during implementation. During wrap-up, Noca also reported cc-253 as not found. Its current status could not be verified, so no duplicate ticket was created.

## Final thoughts

Limits on a role ability should govern that ability's eligibility without preventing ordinary actions. Regression coverage should check both successful fallback behavior and preservation of state when a request needs a choice or is rejected.

The backend fix and its tests are complete. Projection alignment remains the previously filed follow-up: when that implementation is available, verify direct and charter eligibility with a spent ability, both-card choice, and rejection of another special move. No additional backend test ticket is needed for scenarios already covered. This wrap-up leaves only this postmortem uncommitted and makes no further code changes.
